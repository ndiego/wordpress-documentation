# WordPress documentation

The WordPress user documentation, reimagined: Markdown on GitHub, imported into a WordPress site, written for
people who are new to WordPress and for the AI assistants that increasingly read documentation on their behalf.

Status: proof of concept, started 2026-10-26. This repository is one half of an end-to-end demo of how
wordpress.org/documentation could work. The other half, the site that renders it, is
[wordpress-documentation-site](https://github.com/ndiego/wordpress-documentation-site). Background: the research and
proposal in [wp-docs-platform](https://github.com/ndiego/wp-docs-platform) and the HelpHub conversion in
[wp-documentation-migration](https://github.com/ndiego/wp-documentation-migration).

## What is different from wordpress.org/documentation today

| Today | Here |
|---|---|
| 321 articles edited in wp-admin, no review step, no history outside revisions | Markdown files, every change a pull request with CI, history in git |
| Organized by wp-admin screen and a flat category taxonomy | Organized by what the reader is doing: Get started, Write and edit, Design your site, Manage your site; a block reference; Classic WordPress kept apart |
| One page type | Four: tutorial, guide, concept, reference, shown on the page |
| Screenshots taken by hand, aging with every release | Screenshots rendered from specs against a pinned WordPress, re-rendered on a release |
| No Markdown source, no index for agents | Every page as Markdown at its URL plus `.md`, `llms.txt`, a JSON index, Copy page, Open in ChatGPT or Claude |
| Nothing about AI | A WordPress and AI section, with honest placeholders for what is not shipped |

## Layout

```
docs/               the documentation; the folder tree is the structure (STRUCTURE.md)
  README.md         the home page prose
  get-started/      an ordered path for someone new
  write/            the editor, blocks, media, publishing, organizing, comments
  blocks/           the block reference, one page per core block
  design/           themes, the Site Editor, patterns
  manage/           dashboard, settings, users, plugins, updates, security, troubleshooting
  ai/               WordPress and AI
  classic/          the Classic Editor, widgets, Customizer, menus
  assets/           rendered screenshots (docs/assets/screenshots/<page>/<id>.webp)
manifest.json       generated by scripts/build-manifest.py; what the site imports. Do not edit.
conventions/        the Markdown flavor, front matter, style
screenshots/        screenshot specs and config for the wp-docs-toolkit engine
scripts/            build-manifest.py, validate.py, check-links.py, port.py
STRUCTURE.md        the information architecture and the map from today's pages
AGENTS.md           how to add, fix or move a page
```

## Working here

```sh
python3 -I scripts/validate.py          # front matter, links, images, Markdown rules
python3 -I scripts/build-manifest.py    # regenerate manifest.json
python3 -I scripts/check-links.py       # anchors and cross-page links (report)
```

No dependencies beyond Python 3.11. Screenshots need Node 24 and the toolkit; see `screenshots/README.md`.
